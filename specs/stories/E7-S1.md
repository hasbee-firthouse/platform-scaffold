# E7-S1 — Entitlements & upgrade notice

**Epic:** E7
**Layer:** Service
**Group:** F
**Depends on:** E1-S4, E5-S1, E3-S4

## Description

Entitlement defaults from manifests/config, per-org overrides, the check API on PlatformContext, and the upgrade-notice UI whose CTA is a contact link (no plans or checkout).

## Acceptance Criteria

1. `entitlements.get(orgId, key)` returns the per-org override when present, else the declared default (boolean or number).
2. `entitlements.require(orgId, key)` throws a typed 403 `ENTITLEMENT_REQUIRED` when unmet.
3. `entitlement_override(org_id, key, value jsonb, ...)` persists overrides and changes are audited.
4. The web client renders `ENTITLEMENT_REQUIRED` as an upgrade notice whose CTA is a contact link (mailto `email.fromAddress`, or `branding.supportUrl` when set) with no plan picker or checkout.
