# E9-S1 — Complete the inherited shell and account settings experience

**Epic:** E9
**Layer:** API + UI
**Group:** K
**Depends on:** E3-S1, E3-S2, E3-S4, E4-S2, E4-S3, E5-S3

## Problem

The running scaffold has functional routing and APIs, but the inherited application shell is incomplete relative to `SPEC.md` §7.2, §8.2, §16, and §17 and the E3-S4 design artifact. The branded sidebar header, top bar, user menu, profile screen, password-change UI, dark-theme control, and consistent content panels are missing. This leaves core account actions inaccessible and makes inherited screens appear only partially styled.

## Acceptance Criteria

1. The authenticated organization shell renders the configured product logo/name, active organization context, responsive sidebar, top bar breadcrumb, and consistent content panel hierarchy.
2. The top bar exposes an accessible light/dark theme control and a user menu showing the signed-in user's initials, name, and email.
3. The user menu links to Profile and Security, and Sign out calls `POST /api/auth/sign-out`, clears the cached session, and returns the user to `/sign-in`.
4. Profile settings display the current avatar-less identity and update a trimmed name through `PATCH /api/me/profile`; the API rejects unauthenticated, empty, over-120-character, and unknown-field requests.
5. Security settings provide password change, active-session listing, and other-session revocation. Password change requires the current password, a new password of at least 10 characters, matching confirmation, and calls `POST /api/auth/change-password`.
6. Organization settings and reference-workspace screens use the shared token-driven panel/card/table system with readable muted text and responsive behavior; no product color is hard-coded in component code.
7. Production-CSS, UI component, route integration, API route, lint, typecheck, build, and live Docker checks cover the completed behavior.

## Out of Scope

- New onboarding/create-organization behavior
- Enterprise SSO/MFA and linked-account mutation controls
- Reference-workspace feature additions such as task editing or new export behavior
- Changes to the identity adapter or database schema
