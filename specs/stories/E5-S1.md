# E5-S1 — Authorization model & enforcement

**Epic:** E5
**Layer:** Service
**Group:** E
**Depends on:** E1-S3, E2-S1, E4-S2

## Description

Permission strings, code-defined built-in and module roles, manifest registration with boot-time validation, the requirePermission preHandler, the client <Can> gate, and a CI static check that every route declares a permission or is explicitly public.

## Acceptance Criteria

1. Built-in roles resolve: `owner` has all permissions, `admin` all except org delete/ownership-transfer, `member` read + module defaults; wildcards are expanded at role-definition time.
2. The registry refuses boot when a manifest references an unknown permission or duplicates a permission id.
3. A route protected by `requirePermission("x.y.z")` returns 403 `FORBIDDEN` for a member lacking it and passes for one holding it.
4. The static CI check fails when any registered route lacks both an explicit permission and a `public: true` marker.
