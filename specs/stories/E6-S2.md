# E6-S2 — RLS backstop policies

**Epic:** E6
**Layer:** Repository
**Group:** H
**Depends on:** E6-S1

## Description

Every tenant table carries org_id and an RLS policy keyed on current_setting(app.org_id) with FORCE ROW LEVEL SECURITY. The runtime DB role is not the table owner and cannot bypass RLS; migrations run as a separate privileged role.

## Acceptance Criteria

1. Every tenant table has `org_id uuid not null` and a policy `USING (org_id = current_setting('app.org_id', true)::uuid)` with `FORCE ROW LEVEL SECURITY`.
2. The runtime DB role is not the table owner and cannot disable or bypass RLS.
3. A direct SQL query as the runtime role with `app.org_id` set to org A returns zero rows belonging to org B.
