# Data Models — platform-scaffold

> Faithful to `SPEC.md` §19 (core schema), §8.1 (better-auth), §9 (tenancy), §11 (entitlements),
> §12 (audit), §18/§19 (reference module). Conventions (§19): **uuid v7 PKs**,
> `created_at`/`updated_at` everywhere, `org_id + FK` indexes on tenant tables, soft delete only
> where a flow needs it (organizations). All DDL via drizzle-kit migrations.

## Conventions

- **PK**: `id uuid` default uuid v7 (time-ordered) unless a table is better-auth-owned and uses
  its own id type — better-auth ids are text/uuid; represented here as `uuid`/`text` per its adapter.
- **Timestamps**: `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL
  DEFAULT now()` (touched on update). better-auth tables carry its own `createdAt`/`updatedAt`.
- **Tenant tables** carry `org_id uuid NOT NULL` + RLS `USING (org_id = current_setting('app.org_id',
  true)::uuid)` + `FORCE ROW LEVEL SECURITY` (§9.3, D11). Tenant tables in v1:
  `entitlement_override`, `audit_log` (org-scoped rows), `workspace`, `task`.
- **Ownership model** (D7): all resource ownership is `org_id`; there is no user-owned-resource path.
- **Naming**: snake_case columns in SQL; the API/Zod layer maps to camelCase (see api-contracts.md).

## A. better-auth-owned tables (SPEC.md §8.1, §19)

Generated by the better-auth CLI into Drizzle schema files inside `platform-db`, migrated with
everything else. Extended where noted. better-auth manages reads/writes through its adapter;
the tenancy/authz packages build on these tables rather than duplicating them.

### A.1 `user`

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK (better-auth id) |
| name | text | no | display name |
| email | text | no | UNIQUE |
| email_verified | boolean | no | default false; password sign-in blocked until true (§21.8) |
| image | text | yes | avatar URL (unused chrome in v1, §17) |
| created_at | timestamptz | no | default now() |
| updated_at | timestamptz | no | default now() |

Indexes: `UNIQUE(email)`. Not a tenant table (a user spans orgs). Extended with profile fields
directly rather than a parallel table (§8.1).

Example:
```json
{ "id": "018f...", "name": "Ada Lovelace", "email": "ada@acme.com",
  "email_verified": true, "image": null,
  "created_at": "2026-07-15T10:00:00Z", "updated_at": "2026-07-15T10:00:00Z" }
```

### A.2 `session`

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK |
| user_id | uuid | no | FK → user(id) ON DELETE CASCADE |
| token | text | no | UNIQUE; session token (cookie value), hashed handling by better-auth |
| expires_at | timestamptz | no | 30-day sliding expiry (§8.1) |
| ip_address | text | yes | |
| user_agent | text | yes | |
| created_at | timestamptz | no | default now() |
| updated_at | timestamptz | no | default now() |

Indexes: `UNIQUE(token)`, `INDEX(user_id)`. Revocable (Security screen "sign out other
sessions", §8.2.3). Cookie-based, httpOnly, SameSite=Lax, Secure in prod; no JWT.

Example:
```json
{ "id": "018f...", "user_id": "018f...", "token": "sess_...", 
  "expires_at": "2026-08-14T10:00:00Z", "ip_address": "203.0.113.4",
  "user_agent": "Mozilla/5.0", "created_at": "2026-07-15T10:00:00Z", "updated_at": "2026-07-15T10:00:00Z" }
```

### A.3 `account`

Links auth providers to a user (email/password credential + Google social). Account linking
merges same-verified-email accounts (§8.2.7).

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK |
| user_id | uuid | no | FK → user(id) ON DELETE CASCADE |
| account_id | text | no | provider account id (Google sub, or user id for credential) |
| provider_id | text | no | "credential" \| "google" |
| access_token | text | yes | OAuth |
| refresh_token | text | yes | OAuth |
| id_token | text | yes | OAuth |
| access_token_expires_at | timestamptz | yes | |
| scope | text | yes | |
| password | text | yes | hashed (credential provider only) |
| created_at | timestamptz | no | default now() |
| updated_at | timestamptz | no | default now() |

Indexes: `INDEX(user_id)`, `UNIQUE(provider_id, account_id)`.

| expires_at | timestamptz | no | |

| updated_at | timestamptz | no | default now() |

Indexes: `INDEX(identifier)`.

### A.5 `organization`  *(extended: type, deleted_at, slug)*

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK |
| name | text | no | |

### A.6 `member`  *(user, org, role)*

| Column | Type | Null | Constraints / Notes |

Example:

### A.7 `invitation`  *(email, role, token, expires_at, status)*

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK |
| organization_id | uuid | no | FK → organization(id) ON DELETE CASCADE |
| email | text | no | invitee email |
| role | text | no | 'admin' \| 'member' assigned on accept |
| inviter_id | uuid | yes | FK → user(id) |
| status | text | no | 'pending' \| 'accepted' \| 'revoked' \| 'expired' |
| expires_at | timestamptz | no | 7-day single-use (§9.2) |
| created_at | timestamptz | no | default now() |
| updated_at | timestamptz | no | default now() |

Indexes: `INDEX(organization_id)`, `INDEX(email)`, `INDEX(status, expires_at)` (for expiry sweep
job). Token material is single-use and hashed (§21.9). The invite-expiry sweep job flips stale
`pending` → `expired` (§14).

Example:
```json
{ "id": "018f-inv-1", "organization_id": "018f-org-a", "email": "grace@acme.com",
  "role": "member", "inviter_id": "018f...", "status": "pending",
  "expires_at": "2026-07-22T10:00:00Z", "created_at": "2026-07-15T10:00:00Z", "updated_at": "2026-07-15T10:00:00Z" }
```

## B. Platform-owned tables (SPEC.md §11, §12, §19)

### B.1 `entitlement_override`  *(TENANT TABLE — org_id + RLS)*

Per-org override of an entitlement key's default (D9, §11).

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK (uuid v7) |
| org_id | uuid | no | FK → organization(id) ON DELETE CASCADE; RLS key |
| key | text | no | entitlement key, e.g. 'workspace.maxTasks' |
| value | jsonb | no | boolean or number (typed on read) |
| updated_by | uuid | yes | FK → user(id) (or null for system:cli) |
| updated_at | timestamptz | no | default now() |
| created_at | timestamptz | no | default now() |

Indexes: `UNIQUE(org_id, key)`, `INDEX(org_id)`. **RLS**: `USING (org_id = current_setting(
'app.org_id', true)::uuid)`, `FORCE ROW LEVEL SECURITY`. Writes are audited (F072). Written only
via operator CLI (§11), never a web endpoint.

Example:
```json
{ "id": "018f-ent-1", "org_id": "018f-org-a", "key": "workspace.maxTasks",
  "value": 250, "updated_by": null, "created_at": "2026-07-15T11:00:00Z", "updated_at": "2026-07-15T11:00:00Z" }
```

### B.2 `audit_log`  *(TENANT TABLE for org-scoped rows — append-only)*

Append-only (§12). `org_id` nullable so system/cross-org events (e.g. sign-in failure before an
org context) can be recorded; org-scoped rows are RLS-filtered in the viewer.

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK (uuid v7) |
| org_id | uuid | yes | FK → organization(id); RLS key when present |
| actor_user_id | uuid | yes | FK → user(id); null for anonymous/system |
| action | text | no | e.g. 'auth.sign_in.success', 'org.created', 'member.role_changed' |
| target_type | text | no | e.g. 'organization', 'member', 'invitation', 'task' |
| target_id | text | yes | id of the affected entity |
| metadata | jsonb | yes | event-specific detail |
| ip | text | yes | request IP (§12) |
| user_agent | text | yes | request UA |
| created_at | timestamptz | no | default now() |

Indexes: `INDEX(org_id)`, `INDEX(action)`, `INDEX(actor_user_id)`, `INDEX(created_at)`. Writer API
exposes only append/`log` — **no update or delete** (F024). **RLS**: `USING (org_id =
current_setting('app.org_id', true)::uuid)` for the org-scoped viewer; system rows with null
`org_id` are only visible to the CLI, not the org-scoped screen. `FORCE ROW LEVEL SECURITY`.

Actions (platform-emitted, §12): `auth.sign_in.success`, `auth.sign_in.failure`,
`auth.sign_out`, `auth.password_reset`, `org.created`, `org.deleted`,
`org.ownership_transferred`, `invite.sent`, `invite.accepted`, `invite.revoked`,
`member.added`, `member.removed`, `member.role_changed`, `entitlement.changed`,
plus module events `workspace.created`, `workspace.deleted`.

Example:
```json
{ "id": "018f-aud-1", "org_id": "018f-org-a", "actor_user_id": "018f...",
  "action": "member.role_changed", "target_type": "member", "target_id": "018f-mem-2",
  "metadata": { "from": "member", "to": "admin" }, "ip": "203.0.113.4",
  "user_agent": "Mozilla/5.0", "created_at": "2026-07-15T12:00:00Z" }
```

### B.3 pg-boss schema (library-owned)

pg-boss (D14) manages its own `pgboss` schema (tables `job`, `schedule`, `archive`, etc.). Not
modeled here; created by pg-boss on start / via its migration. Not a tenant table; job payloads
that carry `org_id` are scoped in handler logic. Documented as library-owned per §19.

## C. Module-owned tables — `reference-workspace` (SPEC.md §18, §19)

Both are **tenant tables** (org_id + RLS) and are covered by the isolation suite (F086). The
module (and thus these tables) is deletable via one directory + one registry line + `pnpm
db:generate` (A8).

### C.1 `workspace`  *(TENANT TABLE)*

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK (uuid v7) |
| org_id | uuid | no | FK → organization(id) ON DELETE CASCADE; RLS key |
| name | text | no | 1..120 chars |
| created_by | uuid | no | FK → user(id) |
| created_at | timestamptz | no | default now() |
| updated_at | timestamptz | no | default now() |

Indexes: `INDEX(org_id)` (§19 org_id + FK on tenant tables). **RLS**: `USING (org_id =
current_setting('app.org_id', true)::uuid)`, `FORCE ROW LEVEL SECURITY`.

Example:
```json
{ "id": "018f-ws-1", "org_id": "018f-org-a", "name": "Launch Plan",
  "created_by": "018f...", "created_at": "2026-07-15T12:10:00Z", "updated_at": "2026-07-15T12:10:00Z" }
```

### C.2 `task`  *(TENANT TABLE)*

| Column | Type | Null | Constraints / Notes |
|---|---|---|---|
| id | uuid | no | PK (uuid v7) |
| org_id | uuid | no | FK → organization(id) ON DELETE CASCADE; RLS key |
| workspace_id | uuid | no | FK → workspace(id) ON DELETE CASCADE |
| title | text | no | 1..500 chars |
| status | text | no | CHECK IN ('open','done') (§18, §19) |
| assignee_member_id | uuid | yes | FK → member(id) (nullable; must be current org member, F084) |
| due_date | date | yes | nullable |
| created_by | uuid | no | FK → user(id) |
| created_at | timestamptz | no | default now() |
| updated_at | timestamptz | no | default now() |

Indexes: `INDEX(org_id)`, `INDEX(workspace_id)`, `INDEX(assignee_member_id)`, `INDEX(org_id,
status)` (open/done filter). **RLS**: `USING (org_id = current_setting('app.org_id', true)::uuid)`,
`FORCE ROW LEVEL SECURITY`. Task creation checks the `workspace.maxTasks` entitlement (default
100) → `ENTITLEMENT_REQUIRED` beyond the limit (F085). On member removal, the assignee is cleared
per membership rules (F084).

Example:
```json
{ "id": "018f-tk-1", "org_id": "018f-org-a", "workspace_id": "018f-ws-1",
  "title": "Draft investor deck", "status": "open", "assignee_member_id": "018f-mem-2",
  "due_date": "2026-07-20", "created_by": "018f...",
  "created_at": "2026-07-15T12:15:00Z", "updated_at": "2026-07-15T12:15:00Z" }
```
